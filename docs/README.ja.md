# OpenTime

[English](../README.md) | 日本語

OpenTime は、GNSS（GPS などの衛星測位システム）から得た正確な時刻を、NTP を通じてネットワーク内の機器へ安定して配信する、オープンソースの時刻同期アプライアンス開発プロジェクトです。

最初の製品モデル **OpenTimeServer** は、個人、ホームラボ、小規模事業者、教育・研究機関でも導入しやすく、常時運用と保守を考慮したラックマウント型タイムサーバーを目指しています。高価になりがちなエンタープライズ向け専用機器と、耐障害性や再現性に課題が残りやすい一般的な自作機との間を埋めることが、このプロジェクトの狙いです。

> [!IMPORTANT]
> 現在は試作計画・要件整理と機構設計用資料の収集を進めている段階です。動作するハードウェアやソフトウェアは、まだこのリポジトリに収録されていません。

## なぜ正確な時刻が必要か

サーバー、ルーター、スイッチ、ファイアウォール、監視装置などの時計がずれると、複数機器のログを正しい順序で追えなくなります。正確に同期された時刻は、障害原因の調査、不正アクセスの追跡、認証や証明書の期限判定、監視イベントの記録などを支える基盤です。

OpenTimeServer は、Cisco やアライドテレシスなどのネットワーク機器、サーバー、仮想化基盤、監視システムから参照できる、安定した時刻基準の提供を目標としています。

## 現在の試作構想

現行の試作計画 v0.2 では、次の構成を想定しています。

- Raspberry Pi Compute Module 5（CM5、eMMC 搭載）2基による Active / Standby 構成
- タイミング用途の GNSS 受信機から取得する時刻情報と PPS 信号
- GNSS 信号を両方の CM5 へ同時に入力する信号分配回路
- `chrony` と `pps-tools` を利用した Linux 上の時刻同期と NTP 配信
- Keepalived / VRRP と仮想 IP による、障害時の自動フェイルオーバー
- 片系統の停止時にも運転を継続する二系統電源と Power ORing
- M5Stack Basic、LED、LED マトリックスを利用した時刻・稼働状態の表示と監視
- microSD カードに依存せず、eMMC、読み取り専用 OS、RAM 上のログを活用する常時稼働向け構成
- 標準的な 19 インチラックに収容できる 1U または 2U の専用筐体

```text
GNSS アンテナ
      │
GNSS 受信機（時刻情報 / PPS）
      │
信号分配回路
      ├──────────────┐
      ▼              ▼
CM5-A（Active）   CM5-B（Standby）
      │              │
      └──── 有線 LAN ─┘
             │
      ネットワーク内の機器
```

クライアントからは仮想 IP を持つ単一の NTP サーバーとして見せ、Active 側の OS、ストレージ、またはネットワークに障害が起きた場合は Standby 側が役割を引き継ぐ構想です。時刻同期、電源、ネットワーク、温度などの状態を前面表示や監視機能から確認できる設計を目指します。

## 開発方針

OpenTime は、単に動作する自作機ではなく、第三者が再現し、検証し、改良できる製品設計を目指します。最終的には以下の成果物をこのモノレポで公開する計画です。

- 回路図とカスタムキャリア基板データ
- ラック筐体の機構・CAD データ
- NTP、冗長化、監視、表示などのソフトウェア
- 部品表（BOM）
- 組み立て、設定、試験、運用の手順

| Phase 1 | CM5 1基と GNSS による時刻受信・NTP 配信の検証 | 未着手 |
| Phase 2 | CM5 2基による Active / Standby 切り替えの検証 | 未着手 |
