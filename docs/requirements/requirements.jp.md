# OpenTime Server - ソフトウェア＆ハードウェア統合要件定義書

## 1. プロジェクトの概要と背景

ネットワークエッジのファイアウォール（OPNsense等）から、コアとなるL3スイッチ（Cisco等）、仮想化基盤（Proxmox VE等）に至るまで、現代のインフラシステムにおいてミリ秒単位の正確な時刻同期は不可欠である。

しかし、ハードウェア・タイムスタンプや高精度なホールドオーバー機能を備えたエンタープライズ向けの専用タイムサーバーは高価であり、個人ユーザー、独立系エンジニア、メイカー、ホームラボ愛好家が導入するにはハードルが高いことが多い。

本プロジェクトの目的は、2基のRaspberry Pi Compute Module 4 (CM4) を使用して、実用的なStratum 1タイムサーバーを構築することである。本システムは、仮想IP（VIP）によるゼロダウンタイムのフェイルオーバーを提供し、ハイエンドの商用アプライアンスに匹敵する機能を実現するとともに、魅力的なハードウェア中心のユーザーインターフェースを備えることを目指す。

ハードウェア設計およびソフトウェア実装を含むプロジェクト全体はモノレポで管理され、オープンソースプロジェクトとして世界に向けて公開される。

## 2. システム・アーキテクチャ

* **コアコンピュート:** Active / Standby構成のデュアルRaspberry Pi CM4モジュール。
* **ベースボード:** 2基のCM4モジュール、外部インターフェース、および信号バッファ回路を統合するカスタム設計のキャリアボード。
* **時刻同期フロー:** 単一のGPSモジュールから取得したNMEAおよびPPS信号を、基板上の論理回路を通じてファンアウト（複製）し、両方のCM4モジュールのGPIOピンに同時に入力する。Ubuntu上で `chrony` と `pps-tools` を使用し、カーネルレベルの時刻同期を実行する。
* **フロントパネル表示:** マトリックスLEDディスプレイにより、ミリ秒レベルの時刻表示と稼働ステータスの視覚化を提供する。
* **スーパーバイザおよびUI:** フロントパネルにM5Stack Basicを統合する。システム全体のウォッチドッグとして機能し、直感的なグローバル・ユーザーインターフェースを提供する。

## 3. 機能要件

* **NTPサーバー機能:**
  ネットワーク内のデバイスからの時刻同期リクエストに対し、正確かつ安定して応答しなければならない。

* **PPS信号処理:**
  GPSモジュールからのPPS（Pulse Per Second）信号をGPIO経由で直接受信し、カーネル割り込みとして処理しなければならない。

* **マトリックスLEDディスプレイを使用したハードウェアUI:**

  * 現在時刻をミリ秒レベルの精度でリアルタイムに表示すること。
  * ActiveノードとStandbyノードの稼働ステータスを視覚的に分離して表示すること。
  * ステータスインジケーターは、ハードウェアのPPS信号に同期して1秒間隔で点滅すること。

* **M5Stack Basicを使用したグローバル操作UIとヘルスモニタリング:**

  * M5Stack Basicは、定期的に両方のCM4モジュールのヘルスチェックを実行すること。
  * 障害を検知した場合、システムは赤色などの画面カラーや表示パターンを用いて視覚的なアラートを提供すること。
  * M5Stack Basicは、多言語対応やタイムゾーン調整を含む、グローバルユーザー向けの設定インターフェースを提供すること。

## 4. 高可用性とフェイルオーバー設計

一般的なエンタープライズの冗長化プラクティスに従い、クライアントデバイスから単一のNTPサーバーとして認識されるよう、透過的な冗長性を実装しなければならない。

* **仮想IPの共有:**
  2基のCM4モジュールは、Keepalived等のVRRPを実行し、単一の仮想IPアドレスを共有すること。

* **シームレスなフェイルオーバー:**
  Active側CM4の障害（OSのクラッシュ、ストレージ障害、ネットワーク切断など）発生時、Standby側CM4が自動的かつ速やかにVIPを引き継ぐこと。これにより、パケットロスを最小限に抑えつつ、継続的な時刻配信を保証する。

## 5. 非機能要件

* **フォームファクタ:**
  標準的な19インチラックマウントと互換性のある、専用の1Uまたは2Uエンクロージャーに収まること。

* **可用性と信頼性:**
  システムは24時間365日の連続稼働を前提として設計され、障害点を最小限に抑えなければならない。

  * microSDカードの使用は固く禁ずる。
  * 起動およびストレージには、CM4上の高耐久eMMCストレージを使用すること。
  * OverlayFSなどの読み取り専用OS戦略を実装すること。
  * フラッシュメモリの摩耗を防ぐため、ログはRAMディスクに出力すること。

* **開発とデプロイメント:**

  * KiCadの回路図、エンクロージャーのCADデータ、C++コード、シェルスクリプトを含むすべてのプロジェクト資産は、単一のGitHubリポジトリでモノレポとして管理すること。
  * 適切なライセンスを定義し、プロジェクトをオープンソースとして公開すること。
