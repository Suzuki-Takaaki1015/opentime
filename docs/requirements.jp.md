# OpenTime Server - ソフトウェア＆ハードウェア統合要件定義書

## 1. プロジェクトの目的と背景 (Overview)
ネットワークエッジのファイアウォール（OPNsense等）から、コアとなるL3スイッチ（Cisco等）、仮想化基盤（Proxmox VE等）に至るまで、現代のインフラシステムにおいてはミリ秒単位の正確な時刻同期が不可欠である。
しかし、高精度なハードウェア・タイムスタンプやホールドオーバー機能を備えたエンタープライズ向けの専用タイムサーバーは非常に高価であり、導入ハードルが高い。
本プロジェクトは、Raspberry Pi Compute Module 4 (CM4) をデュアル搭載し、商用のハイエンド機器に匹敵する「仮想IP（VIP）による無停止フェイルオーバー機能」とロマンあふれるUIを備えた「一般人・ホームラボ向けの実用的なStratum 1 タイムサーバー」を自作し、ハードからソフトまでをモノレポで管理するオープンソース・プロジェクト（OSS）として世界に公開することを目的とする。

## 2. システム全体構成 (Architecture)
* **コアモジュール:** Raspberry Pi CM4 × 2基（Active / Standby構成）
* **基板構成:** 2基のCM4と各種インターフェース、信号バッファ回路を統合する自作キャリアボード。
* **時刻同期フロー:** 1つのGPSモジュールから取得したNMEA/PPS信号を基板上の論理回路でファンアウト（複製）し、両方のCM4へ同時入力。Ubuntu上でカーネルレベルの時刻同期（chrony + pps-tools）を実施。
* **フロントエンド表示:** マトリックスLEDによるミリ秒単位の時刻表示および稼働ステータス表示。
* **スーパーバイザ＆UI:** M5Stack Basicをフロントパネルに統合。システム全体の死活監視（Watchdog）を行うとともに、全世界のユーザーが直感的に操作できるグローバルUIを提供する。

## 3. 機能要件 (Functional Requirements)
* **NTPサーバー機能:** ネットワーク内の機器からの時刻要求に対し、高精度かつ安定して応答できること。
* **PPS信号処理:** GPSモジュールからのPPS信号をGPIOで直接受け取り、カーネル割り込みとして処理できること。
* **ハードウェアUI（マトリックスLED）:**
    * 現在時刻をミリ秒単位でリアルタイム表示すること。
    * Active側とStandby側の稼働ステータスを視覚的に分割表示し、PPS信号に同期して1秒周期で点滅させること。
* **グローバル操作UI・死活監視（M5Stack Basic）:**
    * 両CM4のヘルスチェックを定期的に行い、障害発生時は画面カラー（赤など）や表示パターンで視覚的アラートを出すこと。
    * 多言語対応やタイムゾーン変更などの設定インターフェースを担うこと。

## 4. 冗長化・フェイルオーバー設計 (High Availability)
エンタープライズ機器のデファクトスタンダードに準拠し、クライアント側から単一のNTPサーバーとして見えるよう透過的な冗長化を実装する。
* **仮想IP（VIP）の共有:** 2基のCM4間でVRRP（Keepalived等）を稼働させ、1つの仮想IPアドレスを共有する。
* **シームレスなフェイルオーバー:** Active側のCM4（OS、ストレージ、ネットワーク等）に障害が発生した場合、即座にStandby側がVIPを引き継ぎ、パケットロスを最小限に抑えて時刻配信を継続する。

## 5. 非機能要件 (Non-Functional Requirements)
* **フォームファクタ:** 19インチラックマウントに適合する1U、または2Uの専用筐体に収めること。
* **可用性・信頼性:** 24時間365日の稼働を前提とし、障害発生率を最小化する。
    * microSDカードの使用を全面的に禁止する。
    * ストレージはCM4搭載の高耐久eMMCを使用する。
    * OSのRead-Only化（OverlayFS等）を行い、ログはRAMディスクへ逃がすことでフラッシュメモリの寿命枯渇を防ぐ。
* **開発・運用形態:**
    * 回路図（KiCad等）、筐体設計、C++/シェルスクリプト等の全コードを1つのGitHubリポジトリ（モノレポ）で管理する。
    * ライセンスを整備し、OSSとして公開する。
